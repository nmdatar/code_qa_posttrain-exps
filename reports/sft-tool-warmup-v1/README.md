# Tool-only SFT warm-start pilot (preregistered before optimization)

**Completed:** sampled formatting improved, but end-to-end quality declined. **Do not promote.** See [results, diagnosis and costs](RESULTS.md). Original preregistration follows unchanged.

Question: does a small supervised warm start improve tool/action reliability and retain answer quality on unseen repository families? The previous 80-trajectory GRPO run had 54 action errors and 15 budget exhaustions; strict passes declined 11 to 6 of 32 despite factual reward moving 0.599 to 0.615. This motivates an experiment, not a causal claim that RL caused these failures.

## Frozen intervention

- Start from Qwen/Qwen3.5-4B, fresh rank-8 LoRA, seed 42. Cross-entropy LR 1e-4, batch size 8, exactly one shuffled pass (8/8/8/6), four acknowledged updates. Save optimizer and sampler every update; evaluate at the initial and final checkpoint. The generic every-five-update cadence is inactive for this four-update pilot.
- Thirty distinct training-task lineages across 19 repository families, containing 69 successful tool targets: 31 search_code, 29 read_file, 9 list_files. All admitted before evaluation. The native Qwen chat renderer matches each archived generation prompt exactly. Source contents and hashes, valid arguments, actual successful untruncated observations, and split membership are checked. Invalid/truncated turns end admission of the prefix. One prefix per lineage; deterministic preference for more useful actions, then less context.
- No new teacher generation. Targets are archived base/RL-policy actions, **not expert demonstrations**. Only successful nonempty tool actions receive loss; prompts, observations, empty searches, and all final answers receive no loss. Machine-verified interface correctness does not establish optimal investigation strategy. The seven distinct tasks with historical strict-passing answers are insufficient for a broad answer-SFT release.
- This is an explicitly registered narrower ablation of procedure 04, not its full verified-investigation SFT arm. It intentionally tests interface learning independently of possibly noisy answer labels. All source episodes remain traceable in the hash-bound supervised manifest. No human-gold metadata is asserted, and private references are never in learner messages.
- No rebalancing or higher project cap. Use the existing $550 GRPO ledger within the $1,000 project allocation. Conservative incremental estimate $123.31 plus $0.38 controller reservation; actual token reservations should be lower. Includes 64 evaluation episodes, grading, training and storage. Historical trajectory collection was already paid; incremental collection cost is zero. Historical acquisition cost is sunk and not claimed as free in a from-scratch comparison.

A checkpoint save/load can add inference variation, so the external base sampler is a secondary comparator.

Primary diagnostic: invalid-action observations / generated actions, including invalid JSON, invalid envelope/tool/arguments and invalid submission binding. Report failure counts by type and per-task pairing. Separately report actual nonzero tool exits, truncation, budget exhaustion, completed submissions, strict full-credit passes and mean strict reward (all attempts; unresolved counted as no demonstrated success). Record resolved coverage, generated tokens, tool calls, latency, model/infrastructure reservations, and loss.

An exploratory success requires at least 95% scoring coverage, at least a 25% relative and 2 percentage-point absolute reduction in invalid-action rate, and no more than a 0.02 decrease in mean strict reward versus the within-run untrained control. Report task-paired and repository-clustered bootstrap intervals, including whether they span no improvement. This small seed-42 pilot cannot establish a confirmed improvement or noninferiority; no promotion based solely on training loss. If baseline errors are too scarce, report a floor effect. Do not tune on confirmation or modify thresholds after results.

SFT followed by RL is a subsequent comparison: exact selected SFT weights with fresh optimizer versus the same direct-GRPO recipe and rollout budget. The other chat's tiny GRPO smoke is contextual evidence unless training settings match. This pilot does not claim to test SFT+RL.
